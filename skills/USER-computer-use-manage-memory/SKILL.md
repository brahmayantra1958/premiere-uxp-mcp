# Computer Use 사용과 종료 관리

## 목적

Computer Use가 필요 없는 시간에 자동화 세션·화면 캡처·폴링·대용량 이미지 상태를 유지하지 않아 메모리와 시스템 부하를 줄인다. 실제 UI 작업의 수명주기에 적용하며, 파일·코드·문서·API 작업만 하는 동안에는 Computer Use를 켜지 않는다.

## 절차

1. **켜기 전에 종료 방법부터 확인한다.** 현재 제공되는 도구 설명과 해당 Computer Use 스킬을 읽는다. 사용할 런타임, 이번 작업이 소유할 세션·탭·연결, 문서화된 종료·초기화 수단을 확인한다. 가용성 검사나 종료 방법 조사만을 위해 초기화하지 않는다. 전용 MCP·API·CLI로 현재 작업을 처리할 수 있으면 그 경로를 사용한다.
2. **실제 UI 작업 직전에만 켠다.** 연속된 관찰·조작·결과 확인을 하나의 짧은 작업 묶음으로 한정한다. 다음 UI 확인이 필요할 때 다시 연결한다. 실행 환경에서 비활성화된 기능을 우회해 켜지 않는다.
3. **필요한 화면만 관찰한다.** 대상 창·탭만 조회하고, 접근성 텍스트로 판단할 수 있으면 스크린샷을 생략한다. 화면 구도가 필요한 작업에는 필요한 캡처를 쓴다. 다음 판단에 필요 없는 이미지·base64·상태 이력을 배열이나 전역 변수에 누적하지 않고, 자동 새로고침·주기적 캡처·무한 폴링을 만들지 않는다. 도구가 요구하는 최신 관찰과 입력 후 확인은 유지한다.
4. **작업 전환 전에 반드시 정리한다.** 다음 중 하나면 종료 절차를 먼저 수행하고 그 다음 작업을 시작한다.
   - UI 작업 묶음 완료 또는 최종 응답
   - 코드 작성, 파일 처리, 문서 작성, 검색, 다른 MCP/API 작업으로 전환
   - 사용자 답변·승인 대기 또는 렌더링·생성·다운로드·설치 대기
   - 예외, 도구 오류, 타임아웃, 사용자 Esc·중단
   UI 조작 사이에 결과를 판단하는 짧은 사고 시간마다 재초기화할 필요는 없다. 별도 작업이나 대기로 넘어가는 경계에서 즉시 정리한다.
5. **재개할 때 새 상태를 얻는다.** 정리 전 필요한 재개 지점은 창·탭 식별자, 마지막 확인 결과 등 짧은 텍스트로만 남긴다. 다음 UI 작업이 실제로 필요할 때만 문서화된 방식으로 다시 연결하고 현재 상태를 관찰한다. 이전 스크린샷 ID·좌표·요소 인덱스·핸들을 그대로 입력에 재사용하지 않는다.

### 종료 절차

성공·오류·중단에 같은 정리 경로를 적용한다. 코드로 한 묶음을 실행할 때는 `finally`에 문서화된 해제를 두고, 여러 도구 호출로 구성된 작업은 다음 비UI 도구 호출 전에 정리한다. REPL reset은 해당 런타임 바깥의 reset 도구로 실행한다.

1. 새 UI 입력과 추가 캡처를 중단한다. 이번 작업이 만든 타이머·폴링·구독·스트림이 있으면 지원되는 취소 수단으로 멈춘다.
2. 이번 작업이 소유한 자동화 연결·세션·lease를 현재 도구의 공식 종료 절차로 해제한다. 임시 자동화 탭은 소유권과 종료 정책이 확인된 경우에만 닫는다. 사용자 작업 앱과 보존해야 하는 탭은 유지한다.
3. 남은 이미지·상태 참조를 해제하고 해당 Computer Use REPL의 reset 도구를 호출한다. UI 전용으로 수명주기를 묶어 다른 계산의 유일한 상태를 같은 커널에 보관하지 않는다. 기존 혼합 커널이면 필요한 비UI 결과를 먼저 최소한으로 보존한다.
4. 종료·reset의 반환 결과와 비활성 상태를 유지하는 공식 상태 조회가 제공되면 그 결과로 정리 범위를 확인한다. 정리 확인을 위해 다시 import, 초기화, 캡처, 앱·탭 나열을 하지 않는다.
5. 실패한 해제는 실패로 기록한다. 남은 공식 정리 수단을 적용하고, 완전 종료를 확인할 수 없으면 수행한 정리와 남은 한계를 짧게 보고한다. 정리 실패를 이유로 UI를 재실행하지 않는다.

### 현재 도구별 적용

| 런타임 | 지원되는 정리와 증거 범위 |
|---|---|
| `mcp__node_repl` + `@oai/sky` | 문서화된 세션 종료 기능이 있으면 먼저 사용한다. 확인한 computer-use `26.1007.71326`의 `sky` API에는 stop/disconnect/shutdown이 없다. 현재 제공되는 `mcp__node_repl__js_reset({})`으로 JavaScript 커널·바인딩을 정리한다. 이는 보조 프로세스나 캡처 서비스 종료의 증거를 제공하지 않는다. |
| `mcp__cua_repl` | 선택한 브라우저의 현재 문서에 나온 연결·세션 정리를 먼저 적용한다. `mcp__cua_repl.js_reset({})`은 REPL 바인딩을 지우지만 브라우저 탭·앱을 닫거나 상태를 지우지 않는다. 탭·연결 정리와 reset을 별도로 판정한다. |
| 그 밖의 Computer Use / 브라우저 도구 | 현재 제공된 문서의 종료·해제 수단만 사용한다. 전용 lease·세션 관리자가 있으면 그 계약을 따른다. reset·연결 해제·탭 닫기·프로세스 종료가 각각 무엇을 보장하는지 확인한다. |

위 표는 2026-10-15에 확인한 계약이다. 도구가 바뀌면 현재 문서를 우선하고, 없는 종료 메서드를 만들어 호출하지 않는다.

## 주의사항

- 사용자 중단 뒤에는 자동 복구·재초기화·입력 재시도를 하지 않는다. 가능한 정리만 수행하고 사용자의 재개 지시를 기다린다. 턴 중단으로 정리 도구도 호출할 수 없었다면 다음 재개 시 미완료 정리를 먼저 처리한다.
- 이번 작업이 소유한 자동화 자원만 해제한다. 사용자 브라우저·Blender·Premiere·공유 서비스·다른 작업의 세션을 종료하지 않는다. 프로세스명 일괄 kill, 비공개 helper 실행·프로토콜, 플러그인 제거를 정리 방법으로 사용하지 않는다.
- 앱 포커스 해제, 탭 닫기, `globalThis.sky` 삭제, 호출 중단만으로 전체 종료를 보고하지 않는다. reset 성공은 커널 정리로, 공식 프로세스 종료 확인은 프로세스 종료로 보고한다.
- 메모리 감소량과 부하 개선은 측정했을 때만 수치로 말한다. 스킬 등록이나 reset 성공을 실제 메모리 절감 검증으로 대신하지 않는다. 확인하려고 Computer Use를 다시 켜거나 반복 측정을 상주시켜 부하를 늘리지 않는다.
- 스킬은 행동 지침이며 프로세스를 자동으로 감시·종료하는 상주 프로그램이 아니다. 플러그인 캐시 파일을 수정하지 않고 이 개인 스킬을 적용한다. 별도 외부 작업 권한은 부여하지 않는다.

## 완료(검증) 기준

- UI 작업이 없으면 초기화 호출도 없다. UI를 썼다면 다른 작업·대기·최종 응답보다 정리 호출이 먼저 있다.
- 성공·오류·사용자 중단 모두 정리를 시도했으며, 이번 작업이 만든 캡처·폴링·구독·연결은 제공되는 해제 수단까지 처리했다.
- 정리 도구의 결과가 확인되고, 완료·부분 정리·실패가 구분된다. 확인할 수 없는 보조 프로세스 종료는 미확인으로 남긴다.
- 다른 작업의 세션과 사용자 앱을 보존했고, 정리 이후 실제 UI 필요나 사용자 재개 지시 없이 재활성화하지 않았다.
